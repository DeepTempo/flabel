# High Level Flow

Proposed process name: flabel
NOTE: System time must be in sync across all systems (NTP Requirement)


1. Process is invoked and passed a packet capture file
    1. e.g. 'flabel my-pcap.pcap'
2. flabel processes the packet capture file to identify threats:
    1. Content Inspection
        1. flabel replays the packet capture through the inline content inspection device
            1. with --topspeed option
            2. Prefer Tap/sniffer deployment mode (e.g. single leg off the server interface rather than routed)
    2. Encrypted traffic inspection: Given we are processing gratuitous pcaps after the fact, we cannot do MITM inspection with the inline device, a fingerprinting detection methodology must be used. Process through Zeek
        1. Compare computed JA3/JA4 signatures from the packet capture to our consolidated list.
        2. NOTE: These can be calulated through Zeek.
3. Consolidates all detections into a master list
    1. JSON output
    2. Query inline detection/inspection device for all detections associated with the pcap replay.
        1. Need to programatically bound this query based on the timestamp that the pcap was replayed.
    3. Combine with list of JA3/JA4 detections.
    4. What to store
        1. Threat name (will be available from the inline detection device). {RESEARCH} Can we do this with Ja3/4?
        2. Flow information (complete tuple): src/dst IP, src/dst port, protocol
        3. Timestamp of the detection
        4. Source of the detection (inline vs. JA3/4)
4. Writes the following to a folder with a name that matches the original pcap file:
    1. All Zeek logs generated by processing the pcap
    2. Companion JSON file
    3. File structure: {input-pcap-name}/zeek/{all-zeek-logs} & {input-pcap-name}/labels.json
